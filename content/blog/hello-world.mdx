Welcome to the first locally-authored post on this site. It lives as a plain
`.mdx` file under `content/blog/` and is statically generated at build time,
sitting right alongside the posts pulled from Medium.

## Why MDX?

MDX lets me write in Markdown but drop in real React components whenever prose
isn't enough. The frontmatter above drives the title, description, tags, and
social metadata.

<Callout type="info" title="Good to know">
  This entire callout is a React component embedded directly in Markdown. No
  imports needed — it's registered globally in `mdx-components.tsx`.
</Callout>

## Code blocks

Fenced code blocks are highlighted at build time with
[rehype-pretty-code](https://rehype-pretty-code.netlify.app/) (powered by
Shiki), using a dual light/dark theme that follows the site's theme toggle.

```tsx
import { getAllPosts } from '@/lib/posts'

export function LatestPost() {
  const [latest] = getAllPosts()
  return <h2>{latest.title}</h2>
}
```

Inline code such as `getPostBySlug('hello-world')` works too.

## GitHub-flavored Markdown

Thanks to `remark-gfm`, the same syntax you'd use in a README works here.
Tables, for instance:

| Plugin               | Stage  | What it does                  |
| -------------------- | ------ | ----------------------------- |
| `remark-frontmatter` | remark | Parses the YAML block up top  |
| `remark-gfm`         | remark | Tables, footnotes, task lists |
| `rehype-slug`        | rehype | Adds `id`s to headings        |
| `rehype-pretty-code` | rehype | Highlights code with Shiki    |

Text can be ~~struck through~~ when a plan changes, and checklists render as
real (non-interactive) checkboxes:

- [x] Write the post in MDX
- [ ] Remember to flip `draft` before shipping

Footnotes work too[^1], and a bare link like https://nextjs.org is turned into
an anchor automatically — no angle brackets required.

## A quick warning

<Callout type="warning" title="Drafts stay hidden">
  Set `draft: true` in the frontmatter and a post is excluded from production
  builds while remaining visible during local development.
</Callout>

That's the whole pipeline — write Markdown, sprinkle in components, ship.

[^1]:
    Footnote definitions can live at the bottom of the file; the plugin
    collects them into a linked list at the end of the rendered post.
